# ヒット&ブロー（hit-and-blow）

## 概要

**一言ルール：隠れたマークの並びを順番に予想する。誰かが当てたとき、一番遠かった人が負け。**

マスターマインド（ヒット&ブロー）を全員で1つの盤を囲んで遊ぶ形にしたもの。縦に並んだマークの答えを、手番の人が1回ずつ予想していく。
予想にはヒント（● 位置も合っている数 / ○ マークだけ合っている数）が付き、全員がそれを見て推理を進める。
**タブレット1台をテーブルに置いたまま遊ぶ** ことを想定したゲーム。

| 項目 | 内容 |
| --- | --- |
| 人数 | 2〜10人 |
| 時間 | 1〜3分 |
| 進行 | 手番制 |
| 共有端末 | ◎（目隠しなし。手番の人がそのまま押す） |
| 各自スマホ | ○ |
| 隠し情報 | 答えの並び（全員に隠れている） |

## ルール

1. 答えは6種類のマーク（🍺🍷🍶🥃🍸🍹）を4個（設定で5・6個）縦に並べたもの。**同じマークが何度入ってもよい**。
2. 開始プレイヤーはランダム、あとは席順。手番の人はマークを **上のマスから順に** 選んで並べ、「予想する」。
3. 予想にはヒントが付く。どのマスが合っているかは分からない。
   - ● …マークも位置も合っている数
   - ○ …マークは答えにあるが、位置が違う数（同じマークは答えにある個数までしか数えない）
4. 誰かが全部 ● にしたら決着。答えを開示して3.5秒見せてから結果画面に移る。

### 負けの決め方

ヒット&ブローは「当てた1人」しか決まらないので、そのままでは飲む人が決まらない。そこで **正解が出た時点で、正解から一番遠かった人** を負けにする。

- 各自の **一番良かった予想** を ●2点・○1点 で採点する。正解者を除いて、点数が一番低い人の負け。同点なら共通のルーレット。
- まだ1回も予想していない人は対象外（手番が回ってこなかった人が飲むのは理不尽なため）。正解者以外の全員が未予想（1手目で正解）なら、正解者以外の全員でルーレット。
- 予想できるのは全員合わせて **マスの数×2＋4 回**（4個で12回、5個で14回、6個で16回）。使い切ったら答えを開示し、同じく点数が一番低い人の負け（正解者なしなので全員が対象）。推理していれば十分に当たる回数で、ラウンドが長引きすぎないための上限。

#### 検討した他の案

| 案 | 不採用の理由 |
| --- | --- |
| 勝ち抜け（当てた人から抜け、答えを作り直して続ける） | 1問に全体で5〜6手かかるので、人数分の問題を解くと1ラウンドが長くなりすぎる |
| 正解の直前の人が負け（次の人にヒントを渡した人） | 情報の少ない手で様子見するのが最善になり、ゲームが進まなくなる |
| 当ててしまった人が負け（ヒントと矛盾する手は禁止） | 推理付きのロシアンルーレットになり当てるゲームでなくなる。酔っていると矛盾チェックで何度も弾かれてつらい |

採用した案では、全員が本気で当てに行くのが最善手のまま（自分が当てられなくても、点数を稼いでおくほど安全）になる。

### 待ち時間とおまかせ

- 制限時間なし。
- おまかせ：並べ途中のマスはそのまま使い、空いているマスをランダムなマークで埋めて予想する。

## 画面設計

- 席順のチップ（手番・NEXT・各自の最高点）、「〇〇 の番」「直前：〇〇 の予想は ●1 ○2」。
- 盤の上に「6種類から4個（同じマークもあり）/ 残り 〇 回」。
- 予想は **縦の列** で左から右へ並べる。列の上に予想した人のアイコン、下にヒント（● / ○ のピン）と点数。直前の予想の列はオレンジの枠。
  - 列が増えると横に伸びるので、盤の中だけ横スクロールし、列が増えるたびに右端（最新）までスクロールする。
- 手番の人の列は点線で一番右に出す。並べ途中のマークも全員に見える（各自スマホでも口を出せるように、並べる操作もサーバーに送る）。
- マークはパレットからタップすると上の空いているマスに入る。列の中のマークをタップするとそのマスが消え、次のマークはそこに入る。全部埋まったら「予想する」。
  - 置く・消すの操作は「何をしたか」だけを送る（並び全体を送ると、素早く2回タップしたときに古い並びで上書きしてしまう）。
- 絵文字だけでは見分けにくいので、マークごとに地の色を変える。
- 決着したら一番右に「答え」の列を出す。

## 設計

```ts
interface HitAndBlowConfig { slots: 4 | 5 | 6 }

interface HitAndBlowState {
  phase: 'turn' | 'shown' | 'done';
  slots: number;
  answer: number[];              // MARKS のインデックス（setup で決める）
  maxGuesses: number;            // slots * 2 + 4
  guesses: Guess[];              // { playerId, marks, hits, blows, auto }
  draft: (number | null)[];      // 手番の人が並べている途中
  order: PlayerId[];
  turnIndex: number;             // 最初の人（手番は order[(turnIndex + guesses.length) % n]）
  solvedBy: PlayerId | null;
}

type HitAndBlowAction =
  | { type: 'put'; mark: number }   // 上の空いているマスに置く
  | { type: 'clear'; slot: number } // そのマスを空ける
  | { type: 'guess' };              // 全部埋まっていれば予想する
```

- `tableView` の `answer` は `shown` になってから返す（それまではクライアントに答えを送らない）。
- 正解または予想の使い切りで `shown` にしてタイマー `finish` を設定し、`finish` で負けを決めて結果を返す。
  - 結果を返すとルームがすぐ結果画面に移るため、開示と結果を分けている（ロシアンルーレットと同じ）。
- `pendingPlayers`：`turn` 中は手番の人、それ以外は空。
