# あみだくじ（amidakuji）

## 概要

**一言ルール：縦線を選んで横線を1本ずつ足す。ハズレにたどり着いた人が負け。**

人数分の縦線のうち、下端の1つがハズレ。はしごの下半分は紙を折ったように隠れていて、そこには最初から横線が引いてある。
全員がスタートを選んで、見えている上半分に横線を1本ずつ足したら、隠れた部分を開いて1人ずつたどる。
「こっちに引くな！」と言い合いながら線を足し、たどる瞬間をみんなで見守るゲーム。
**タブレット1台をテーブルに置いたまま遊ぶ** ことを想定している。

| 項目 | 内容 |
| --- | --- |
| 人数 | 2〜10人 |
| 時間 | 1分 |
| 進行 | 手番制 |
| 共有端末 | ◎（目隠しなし。手番の人がそのまま押す） |
| 各自スマホ | ○ |
| 隠し情報 | 隠れた部分の横線（全員に隠れている） |

## ルール

1. 縦線は参加人数と同じ数。下端の1つがハズレ（💀、最初から見えている）。
2. **スタートを選ぶ**：開始プレイヤーはランダム、あとは席順。上端の空いている番号を1つ選ぶ。最後の人には残った1つを自動で配る。
3. **横線を足す**：同じ順番で、見えている上の部分（5段）に横線を1本ずつ引く。
   - 横線は隣り合う縦線をつなぐ。同じ段で隣り合う場所・同じ場所には引けない（どちらに進むか決まらなくなるため）。
4. **たどる**：全員が引いたら隠れた部分を開き（2秒）、開始プレイヤーから席順に1人ずつたどる（1人 1.8 秒）。ハズレにたどり着いた人が出たらそこで止め、2.5秒見せてから結果画面に移る。残りの人はたどらない。

- 縦線とゴールが人数分なので、ハズレにたどり着くのは必ず1人で、1ラウンドで決まる。
- 「アプリである意味」は、全員に隠れた横線をアプリが用意すること（紙でやると線を隠す係が1人必要で、その人は遊べない）と、たどる作業の自動化にある。

### 確率が全員同じになる仕組み

ハズレが見えているので、何もしないと「ハズレから遠い縦線を先に取る」「最後に引く人が自分の線をずらす」ことで有利になってしまう（毒入りチョコで起きた後手有利の問題。[rejected.md](./rejected.md)）。
そこで隠れた部分の **一番下の n 段（n = 人数）** は、一様ランダムに選んだ並べ替えを奇偶転置ソートの形で横線にしたものにする。

- 奇偶転置ソートは n 回の「隣同士を比べて入れ替える」で必ず並べ終わるので、n 段あればどんな並べ替えも横線で表せる。同じ段の比較は1つおきの隙間なので、横線が隣り合うこともない。
- 隠れた部分の出口の並びが一様ランダムなので、その上でどの縦線を選んでも、どんな横線を足しても、ハズレにたどり着く確率は全員ちょうど 1/人数 になる。
- 見た目のために、その上に3段だけ、ランダムな横線を置く段を加えている（結果には影響しない）。

### 待ち時間とおまかせ

- 制限時間なし。
- おまかせ：スタート選びなら空いている縦線、横線なら引ける場所からランダムに選ぶ。

## 画面設計

- 席順のチップ（手番・NEXT）、「〇〇 の番：スタートを選ぶ / 横線を1本引く」「直前：〇〇 が 2 番を選んだ / 横線を引いた」。
- 縦線の上に番号ボタン（選ばれたら選んだ人のアイコン）、下にゴール（○ と 💀）。
- 隠れた部分は「？？？」の斜線のカバーで覆う。開くとカバーが落ちて消える。
- スタートの番号はタップするとすぐに決まる（ロシアンルーレットと同じくテンポ優先）。
- 横線は引ける場所を点線で出し、タップするとすぐに引く。他の盤のゲームは「選択 → 確定」の2段階だが（[common-design.md](./common-design.md#共有端末での隠し情報ホットシート)）、横線は1本引くだけで結果への影響もないので、テンポを優先して確定を省いた。
- プレイヤーが引いた横線は、引いた人の色で塗る。
- たどるときは、その人のアイコンが線の先と一緒に上から下へ進み（CSS の `offset-path`）、着いたゴールにアイコンが出る。たどり終えた人の線は細くして、今たどっている人の線を目立たせる。ハズレのゴールは黄色く光る。
- 盤の縦線の間隔は画面幅に合わせる。盤の幅を `ResizeObserver` で測り、SVG はピクセル単位で描く。上下の番号・ゴールは同じ列幅の CSS グリッドで並べる。
  - SVG を `preserveAspectRatio="none"` で伸ばす方法は使わない。線を `non-scaling-stroke` にすると `pathLength` を使った線を引くアニメーションの長さがずれ、線の切れ端が別の場所に出てしまう。

## 設計

```ts
type AmidakujiConfig = Record<string, never>; // 設定なし

interface Rung { row: number; gap: number; by: PlayerId | null } // row 段目で縦線 gap と gap+1 をつなぐ

interface AmidakujiState {
  phase: 'start' | 'line' | 'open' | 'trace' | 'shown' | 'done';
  columns: number;               // 縦線の数（人数）
  openRows: number;              // 横線を足せる上の段数（5）
  hiddenRows: number;            // 隠れた段数（3 + 人数）。row は openRows から
  hidden: Rung[];                // 最初から隠れている横線（setup で決める）
  added: Rung[];                 // プレイヤーが足した横線
  hazure: number;                // ハズレのゴール
  startBy: (PlayerId | null)[];  // 縦線ごとにスタートに選んだ人
  order: PlayerId[];
  turnIndex: number;             // 最初の人。スタート選び・横線・たどる順はすべてここから席順
  turns: number;                 // 今のフェーズで操作した人数
  lastMove: Move | null;
  traced: number;                // たどり終えた人数
}

type AmidakujiAction =
  | { type: 'start'; column: number }
  | { type: 'line'; row: number; gap: number };
```

- `tableView` の `hidden` は `open` になってから返す（それまではクライアントに隠れた横線を送らない）。`loser` は `shown` になってから返す。
- たどる処理 `trace()` と、横線を引けるかの判定 `canPlace()` はクライアントと共有する（たどった線の描画・点線の表示に使う）。
- 全員が引いたら `open` にしてタイマー `trace` を設定。`trace` のたびに `traced` を1つ進め、ハズレの人をたどったら次はタイマー `hit` で `shown` にし、タイマー `finish` で結果を返す。
  - 結果を返すとルームがすぐ結果画面に移るため、たどる演出と結果を分けている。
- `pendingPlayers`：`start`・`line` 中は手番の人、それ以外は空。
